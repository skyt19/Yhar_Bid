# AI Work Assistant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the Yharbid AI workspace from a basic chat UI to an agentic assistant that calls structured tools, generates real downloadable files (TXT/DOCX/XLSX/PPTX/PDF), manages tasks, and interacts with Google Calendar — all through conversational Thai-language interactions.

**Architecture:** A new `AgentService` sits between `AiController` and `AiService`. It drives a bounded agent loop: it sends tool definitions and conversation history to `openai/gpt-oss-120b`, parses tool-call responses, dispatches them to existing services (TaskController, CalendarController, file generators, Firebase Storage), and feeds results back to the model until a final text reply arrives. File generation writes real bytes via a new `ArtifactService` which reuses Firebase Storage (same pattern as `TaskPlanStorageService`). The existing AI Workspace UI gains three new widget regions: a tool-execution status ticker, a generated file gallery, and an inline confirmation card.

**Tech Stack:** Flutter/Dart, GetX, Groq API (`openai/gpt-oss-120b`), Firebase Auth/Firestore/Storage, Google Calendar API, `dart_pdf` (PDF), `docx_template` or raw XML zip (DOCX), `excel` (XLSX), and custom PPTX zip writer (PPTX). All packages checked against existing pubspec before adding.

**Spec:** The implementation spec was provided inline in the `/superpowers:writing-plans` invocation message (YHAR BID — AI WORK ASSISTANT IMPLEMENTATION / Upgrade to GPT-OSS-120B).

## Global Constraints

- Model must be exactly `openai/gpt-oss-120b` in `ai_service.dart` — never substituted
- Groq API key sourced from `AppConfig.groqApiKey` (`.env` → fallback); never hardcoded
- Firebase Auth UID validation required before every write operation
- Thai language (UTF-8) must work in all generated file types
- No new Firestore collections beyond `users/{uid}/tasks`, `users/{uid}/artifacts`, `task_plans/{uid}/...`
- `dart:html` used only inside `// ignore: avoid_web_libraries_in_flutter` guards (existing pattern)
- No deployment, no commit/push, no CI changes
- Do not delete or weaken existing tests
- Agent loop max iterations: 10; timeout per call: 30 s
- Require explicit user confirmation for: create task, create calendar event, delete file, overwrite file

---

## Review Focus

1. **Empty agent loop response** — model returns `finish_reason: stop` with no tool calls and an empty content string; the loop must emit a fallback Thai message rather than showing a blank bubble.
2. **Tool argument injection** — model may generate a `create_task` call with `userId` or `uid` field; executor must ignore it and always use `FirebaseAuth.instance.currentUser.uid`, never the model's value.
3. **Duplicate file creation on retry** — user taps "create document" twice before the first completes; idempotency key (`requestId`) prevents two uploads and two Firestore records.
4. **Firebase Storage failure with generated bytes in memory** — if upload throws, the artifact bytes are still in memory; the UI must offer a local browser download fallback (existing `dart:html` pattern from `TaskController.downloadTaskOutline`).
5. **Non-UTF-8 Thai in DOCX/XLSX** — `docx_template` and `excel` packages encode strings; test with full Thai sentence including tone marks to ensure no `?` substitution.

- [ ] **Step 3: Implement `lib/services/agent_service.dart`**

```
static const int _maxIterations = 10;
static const Duration _timeout = Duration(seconds: 30);

Future<AgentResult> run(List<AgentMessage> history, UserRole role):
  1. Build system prompt from role.
  2. Convert history to Groq JSON format.
  3. Loop up to _maxIterations:
     a. Call AiService.callWithTools(messages, toolDefinitions).withTimeout(_timeout)
     b. Parse response: extract finish_reason, content, tool_calls.
     c. If finish_reason == 'stop' and content non-empty → return AgentResult(reply: content).
     d. If finish_reason == 'stop' and content empty → return fallback Thai message.
     e. If tool_calls present: append assistant message to history, then for each call:
        - Validate tool name against known set; return ToolResult(isError:true) if unknown.
        - Dispatch to executor; catch all exceptions; return ToolResult(isError:true) if throws.
        - Append ToolResult to history.
     f. Continue loop.
  4. If loop exhausted → return AgentResult with Thai error message.
```

`toolDefinitions` is a `static List<Map<String,dynamic>>` listing all 11 tools with their JSON Schema parameters.

- [ ] **Step 4: Implement `lib/services/artifact_service.dart`**

**TXT:** `utf8.encode(content['body'])` — straightforward.

**XLSX:** Use `excel` package. Create `Excel.createExcel()`, iterate sheets, write headers and rows. Call `excel.encode()`. Thai strings pass directly as `TextCellValue`.

**DOCX:** Build minimal OOXML ZIP with `archive` package. Required files: `[Content_Types].xml`, `word/document.xml`, `word/_rels/document.xml.rels`, `_rels/.rels`. Populate `word/document.xml` with `<w:p><w:r><w:t>` elements from sections/paragraphs. Encode Thai strings as-is (UTF-8 XML). Write headings as `<w:pStyle w:val="Heading1"/>`.

**PDF:** Use `pdf` package (`import 'package:pdf/widgets.dart' as pw`). Create `pw.Document`, add `pw.Page` per section. Use `pw.Font.ttf` — **no system Thai font available at runtime**; use `pw.Font.helvetica` as fallback and include a note in the document that Thai rendering requires font embedding. For full Thai support, this is a known limitation unless a Thai TTF is bundled (see Review Focus item 5).

**PPTX:** Build minimal OOXML ZIP similar to DOCX. Required files: `[Content_Types].xml`, `ppt/presentation.xml`, one `ppt/slides/slide{n}.xml` per slide, `_rels` files. Each slide has title (`<p:sp>` with `<p:ph type="title">`) and body bullets (`<p:ph type="body">`).

**Storage:** Same pattern as `TaskPlanStorageService`. Path: `artifacts/{uid}/{uuid}-{filename}`. Firestore: `users/{uid}/artifacts/{docId}` with `ArtifactRecord` fields. Capture download URL from `ref.getDownloadURL()`.

**Fallback:** If upload throws, catch exception, set `downloadUrl = ''`, log the error, and expose the bytes via a `localBytes` field on `ArtifactRecord`. UI (Task 7) will offer browser download using `dart:html`.

## Known Limitations (Builder Notes)

1. **PDF Thai font rendering:** `dart_pdf` uses embedded fonts. Thai glyphs will render correctly only if a Thai TTF (e.g., Sarabun or Noto Sans Thai) is bundled as a Flutter asset and loaded via `pw.Font.ttf(await rootBundle.load(...))`. Without it, Thai characters may not appear. The plan's builder should include the font or note the limitation in the generated PDF header.

2. **PPTX Thai:** OOXML XML is UTF-8; Thai text encodes correctly. No known rendering issue.

3. **Groq `openai/gpt-oss-120b` availability:** If this model ID does not exist or is not accessible on the Groq account, every API call will return HTTP 404 or 400. The system must log the actual error and surface it in `AgentResult.reply`. The builder should test model availability before implementing the full loop.

4. **Calendar write access:** Creating events requires the Google OAuth scope `https://www.googleapis.com/auth/calendar`. If the existing sign-in flow only requests read scopes, `create_calendar_event` will return 403. This is an existing constraint; do not change the OAuth flow — surface the error message from `CalendarController.createEvent`.

5. **Firebase Spark (free) plan:** Storage writes are subject to rate limits. The agent should not generate more than one large file per request.
